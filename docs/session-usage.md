# 会话用量：数据来源与边界（0.2.36）

点击 Token 胶囊，或点击 5h →「会话用量 · 缓存与上下文」。侧栏通过 5h 菜单进入，原有周额度悬停逻辑不变。沿用胶囊按钮、浅色/深色主题、位置锚点与失焦隐藏规则。

## 不是自动识别当前页面

第一版需要从最多 100 个未归档正常对话的列表中选择对话。扫描最多最近 5000 条元数据，按结构化 `source` 排除 `subagent`，取得 100 个正常对话后停止，不让 Guardian 或其他子任务先占满数量上限。不按标题删除/过滤：正常对话即使叫 Guardian review 也保留；来源缺失或格式无效不冒充已验证正常对话。重新读取选择时再次核验来源，内部任务不继续展示。

Guardian 是 Codex 在「帮我批准」/Auto-review 流程中使用的独立审批审核代理；它的记录存在本机数据库不代表用户创建了很多普通对话。这里只修正列表展示，不删除审核记录、不关闭安全审核、不扣除账户累计量。[OpenAI 官方说明](https://learn.chatgpt.com/docs/sandboxing/auto-review)

面板始终标注「所选会话」，不把最新数据库记录、最近活跃会话或运行中的后台任务当成屏幕上当前打开的对话。选择仅保存在当前胶囊进程内，关闭面板再打开会保留；退出程序后重新选择。未能读取当前选择时不自动切换到其他会话。

## 这些数字不能混用

| 展示 | 来源 | 含义与限制 |
| --- | --- | --- |
| 账户累计 Token | 既有 `account/usage/read` → `summary.lifetimeTokens` | 当前账户累计量，不是当前会话上下文；缺失/错误显示待确认 |
| 所选会话累计 | 本地 SQLite `threads.tokens_used` | Codex 维护的会话累计值，不重建它的内部计费规则 |
| 最近请求输入/输出 | 会话记录 `event_msg.token_count.info.last_token_usage` | 最近一条完整、校验通过的模型请求；不是会话累计，也不包括尚未发送的输入 |
| 缓存输入及命中率 | `cached_input_tokens / input_tokens` | 缓存是输入的子集，不能再加到输入总量中；分母为零时比例未知 |
| 上下文估算 | 最近请求 `total_tokens / model_context_window` | 最近请求快照；不是客户端实时上下文、输入框状态或精确剩余可输入量；不套用模型未知的内部保留空间 |
| 压缩事件 | 本地记录顶层 `compacted` | 本次有限读取中观察到的事件数，不是必然完整的全会话次数，也不计算经济收益 |

输出中的推理 Token 不另外加到输出总量。压缩会改变上下文，但不等于缓存输入：不能宣称「命中 80% 就缩短上下文 80%」，不能把 Token 换算成 Plus 5h/周额度消耗。压缩后若还没有新请求数据，旧上下文估算会清空，提示等待下一次请求。

## 账户 Token 的异常零值

- 不把旧 `usage-cache.ini` 中的账户 Token 当作已验证实时量，启动后等待新的读取。
- 首次零值，或正数突然变成零，先显示「待确认」；同一可识别账户至少两次零值观察、相隔至少 5 秒后才确认真实零值。恢复正数立即正常显示。
- 账户身份只在内存中保存 SHA-256 摘要，不写入邮件地址、身份原文或认证信息；账户变化清空旧账户累计值，不能可靠绑定身份时零值保持待确认。
- 缺失、负值、失败读取不会当成零，读取失败不继续展示旧值为正常。此策略是保守处理，不证明服务器零值一定是错误，也不能纠正接口自身连续返回错误零值的情况。

## 只读、有限读取与隐私

通过 Windows 自带 `winsqlite3.dll` 以 `SQLITE_OPEN_READONLY` 打开最新编号的 `state_N.sqlite`，忙等待最多 200 ms。只查询 `id,title,rollout_path,tokens_used,source` 和用于筛选/排序的元数据，不查询 `first_user_message`、`preview`、消息表或聊天正文；GUID 以 SQL 参数绑定。遇到新版本不兼容数据库时明确失败，不退回旧库冒充新数据。普通本地盘符路径的 Windows `\\?\` 前缀会先规范化，随后仍执行相同的目录、重定向和会话 ID 校验；设备或扩展 UNC 路径不因此放行。

会话日志本身包含聊天内容，因此读取不能描述成「日志文件完全不含正文」。实现只在内存中扫描最多末尾 8 MB，先按头部筛选数字事件；非数字消息不进行 JSON 解析、不展示、不保存、不上传。压缩记录只识别顶层类型，不解析摘要。首条元数据只读取最多 512 字节，用于检查会话 ID；仅允许 Codex `sessions` / `archived_sessions` 下的规范路径，拒绝重定向路径。文件末尾未写完的行跳过，超过 256 KB 的数字事件显示读取上限，不沿用旧请求为最新。

超过 8 MB 时压缩次数标注「仅最近 8 MB」；未验证记录时显示未知，不编造 0 次。面板每 15 秒只读刷新所选会话，并标注请求时间为历史快照。列表刷新按钮不发送任务、不开启续跑、不压缩上下文、不安装 Nudge、不启用调试端口、不注入页面、不修改 Codex 安装文件或数据库。

## 参考实现与官方语义

- [Codex Usage Badge](https://github.com/jaykinhoo9/codex-usage-badge)：参考只读 SQLite 元数据读取与最新库选择思路；MIT，未捆绑其程序、Node 依赖或页面注入代码。这里的 Windows 原生读取器为独立实现。
- [OpenAI Codex TokenUsage 源码](https://github.com/openai/codex/blob/main/codex-rs/tui/src/token_usage.rs)：用于核对最近上下文与累计会话用量的区别；这里展示原始比例估算，不声称与客户端内部保留空间算法完全相同。
- [OpenAI Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)：缓存输入是输入的子集，不等于上下文压缩。
- [OpenAI Compaction](https://developers.openai.com/api/docs/guides/compaction)：核对压缩的作用与边界；本版本不调用压缩接口。

Nudge 本机仅找到已安装可执行程序，缺少可核验源码和开放接口，所以没有直接复用它的实现或宣称完全验证其内部算法。
